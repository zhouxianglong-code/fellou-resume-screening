# 邮箱简历筛选：功能说明

这是交给 Codex 执行的招聘筛选流程和规则，不是独立运行的邮件程序。它需要当前 Codex 环境具备可用的 Gmail 搜索、读取及附件访问能力。

## 功能对应表

| 功能 | 用途与处理方式 | 结果或限制 |
| --- | --- | --- |
| 邮箱检索 | 按用户指定日期、岗位和招聘邮件线索查找简历 | 无连接或附件无法读取时需说明，不能编造候选人 |
| 跨岗位匹配 | 将简历同时与投递岗位及其他合理岗位比较 | 可标记“转岗匹配” |
| 岗位证据评分 | 按岗位画像核对项目、职责、技术和交付成果 | 区分简历自述、已核实事实和推断 |
| 推荐阈值 | 80–100 优先面试；70–79 人工复核；低于 70 不展示详情 | 辅助招聘人员复核，不自动录用或淘汰 |
| 批次数量 | 默认每批检查 10 份新简历，明确指定数量时按请求执行 | “前端、全栈各 10 个”不保证一定存在足够合格且未推荐的人 |
| 历史去重 | 对比候选人、附件和已有筛选记录 | 需要可访问的历史台账；安装 Skill 不会自动带来历史数据 |
| 创业加分 | 研发候选人有创业、独立商业产品或 0 到 1 交付经历时核验证据 | 结合产品、用户、收入或代码归属，不仅凭“创始人”头衔 |
| 正向候选人偏好 | 优先识别 AI Coding、Agent、编辑器、画布、工程工具及真实交付经历 | “林明型”指可复用的能力画像，不要求与某个人身份相似 |
| 当前任职规则 | 现有流程对不足六个月的正式全职经历检查客观例外 | 这是当前配置的规则；具体执行以最新岗位画像和用户修订为准 |
| 标准迭代 | 把招聘反馈和 JD 更新记录到校准文件 | 本地修改不会自动同步到其他人的安装目录或 GitHub |

## 文件在哪里

| 文件 | 负责什么 |
| --- | --- |
| `SKILL.md` | Codex 的执行入口：检索、去重、匹配、评分及报告流程 |
| `references/company-jd-profile.md` | 各岗位要求、评分依据及共同人才画像 |
| `references/positive-resume-patterns.md` | 正向技术候选人特征及证据要求 |
| `references/calibration-log.md` | 规则修订和招聘反馈的来源记录 |
| `agents/openai.yaml` | Skill 在 Codex 中的显示信息和默认提示词 |

## 怎么用

安装后连接自己的 Gmail，在 Codex 中输入：

> 使用 fellou-resume-screening，筛选今天的前端和全栈简历，各推荐最多 10 人，排除历史推荐，70 分以下不展示；人数不足时说明实际人数。

报告应包含姓名或候选人编号、最佳匹配岗位、分数、主要证据、缺口和核实问题。真实简历与去重台账保存在使用者本地，公开仓库只共享规则。
