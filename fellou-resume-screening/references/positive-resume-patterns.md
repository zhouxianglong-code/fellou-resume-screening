# 正向简历模式

这些模式用于提高候选人排序质量，不替代岗位硬门槛、任职稳定性门槛、70 分展示阈值或公平性约束。

## 林明型候选人

优先寻找“林明型”：能把 AI、Agent、工程系统和产品闭环结合起来的人。典型信号包括：

- 做过 Coding IDE、代码理解平台、Agent 工作流、AI 代码生成、Repo/符号索引、工具调用、MCP、Skill、评测集、执行轨迹、可观测性或自动修复系统。
- 做过设计工具、画布、编辑器、Figma 插件、可视化搭建、WebGL/Canvas、互动创作工具、AI 生成原型到生产代码链路。
- 能说明本人在系统设计、核心代码、工程质量、上线交付、用户反馈、客户使用、团队协作或商业结果中的所有权。
- 不只是“用过 Cursor/Claude/Codex”，而是能管理 AI Agent 产出，建立审查、测试、回滚、评测或组件规范。
- 有独立产品、开源工具、创业项目、个人工作室或真实客户交付，并能核验用户、收入、调用量、项目链接、代码、演示或复盘。

## 接近度标记

- `很高`：同时具备 AI/Agent 系统、工程所有权、产品/用户/交付证据，且与当前前端/全栈/Design Engineer 方向强相关。
- `中`：具备其中两类强证据，或技术很强但产品闭环/AI 深度/可核验证据有一项不足。
- `中低`：只有概念、工具使用或局部参与，缺少本人核心贡献、落地结果或可核验证据。
- `无明显证据`：不应为了贴合偏好而强行标记。

## 需要深挖的问题

- 这套 Agent/AI 工程系统中，哪些模块是本人从 0 到 1 设计和实现的？
- 有没有可访问链接、代码仓库、Demo、客户案例、用户数据、收入或交付记录？
- AI 生成代码如何被审查、测试、回滚、评测和维护？
- 如果是编辑器/画布/设计工具，复杂交互、性能、状态管理和组件规范如何处理？
- 创业/独立产品失败或增长不佳时，候选人是否能复盘关键判断和工程取舍？
