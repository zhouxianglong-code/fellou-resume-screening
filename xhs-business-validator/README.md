# 小红书市场调研：功能说明

这是让 Codex 根据小红书笔记和评论辅助验证商业想法的 Skill。它不是小红书简历筛选、自动发帖或账号运营工具。

## 功能对应表

| 功能 | 做什么 | 结果或限制 |
| --- | --- | --- |
| 关键词搜索 | 通过 TikHub API 搜索与商业想法相关的笔记 | 需要用户自己的有效 Token；接口结果不代表全平台样本 |
| 快速模式 | 搜索 1 页，取前 5 篇笔记 | 适合初步判断，实际数量受接口返回影响 |
| 完整模式 | 搜索 2 页，取前 20 篇笔记 | 更多材料不代表统计上有代表性 |
| 互动排序 | 使用点赞 + 收藏×2 + 分享×3 + 评论×3 排序 | 这是取样指标，不是市场验证总分 |
| 评论获取 | 对高互动笔记读取评论 | 受接口权限、返回量和限流影响 |
| 痛点分析 | 分析需求、现有解决方案、市场信号和情绪 | 基于已获得内容，需区分证据与推断 |
| 评论标签 | 从人群场景、功能价值、保障价值和体验价值分类 | 帮助组织需求，不是对真实用户身份的验证 |
| 综合评分 | 结合需求、竞争、反馈、活跃度和内容质量给出 0–100 分 | AI 辅助判断，无固定可复现的加权公式，不是收益预测 |
| 用户画像 | 根据讨论材料概括典型需求和使用场景 | 属于假设画像，不能当作已核实的真实个人属性 |
| HTML 报告 | 生成包含评分、痛点、机会、热门笔记和数据来源的报告 | 写入当前工作目录的 `reports/` |

## 配置和文件

| 文件或配置 | 用途 |
| --- | --- |
| `SKILL.md` | 完整执行说明：API 调用、取样、分析和报告流程；本项目没有独立自动运行程序 |
| `.env.example` | 空白凭证模板，不包含真实密钥 |
| 工作目录 `.env` 中的 `TIKHUB_TOKEN` | 必需，用于调用 TikHub 小红书数据服务 |
| `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` | 可选，大量评论时使用外部兼容模型；默认使用 Codex 自身分析 |
| 工作目录 `data/`、`reports/` | 使用中产生的数据和报告，不随 Skill 公开发布 |

## 怎么用

安装 Skill 后，在自己的工作目录中按 `.env.example` 创建并填写 `.env`，然后在 Codex 中输入：

> 使用 xhs-business-validator，快速验证“面向独立开发者的 AI 测试工具”这个商业想法，输出证据、局限和报告。

TikHub 账户、Token 和服务额度由使用者自行配置；安装脚本不会代为开通。接口发生变化、授权失效或返回数据不足时，应报告实际问题，不能生成虚构的调研结果。
